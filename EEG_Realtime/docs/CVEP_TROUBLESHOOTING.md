# c-VEP 常见问题

完整流程见 [c-VEP 指南](CVEP_GUIDE.md)，时序阈值见[目标数与录制中断](CVEP_TARGETS_AND_INTERRUPTS.md)，启动与网络配置见[根目录说明](../../README.md)。

## 点击开始后没有启动

查看开始按钮附近的状态与拒绝原因，并依次确认：

1. 其他工作台已停止采集或回放，当前设备已连接。
2. 已积累至少 2 秒连续新鲜 EEG，必需通道没有平线或饱和等硬故障。
3. 页面与后台版本一致，显示与时钟检查通过，并已确认闪烁提示。
4. 受试者身份、录制名、目标数和试次数有效。

开始后先显示 2 秒静态提示，再进入刺激。“模拟在线目标”只影响模拟源的在线数据，不设置真实校准标签。

## 录制途中停止

以页面的最终停止原因及该录制的 `manifest.json`、`events.jsonl` 为准。文件保存在 `EEG_Realtime/data/cvep_recordings/`。

| 提示类别 | 检查内容 |
|---|---|
| EEG 超时、缺包、连接断开 | 热点连接、设备电源、收包统计及其他程序是否占用设备 |
| 处理积压 | 电脑负载与数据处理延迟；开始下一轮前等待连续稳定数据 |
| 页面失焦或隐藏 | 保持刺激页面前台可见，避免切换窗口或标签页 |
| 帧报告请求失败或队列溢出 | 本地服务是否仍运行、浏览器是否响应、是否有长时间请求阻塞 |
| 写入失败 | 保存目录权限、可用磁盘空间和错误详情 |

中止后保留已写入文件。先看各目标有效完整试次数，再决定补录数量；不要手动删除告警或改标签提高保留数量。

## 帧间隔告警

当前 12.50–20.833333… ms 的单帧范围包含 20.40 ms。超限会告警并排除受影响试次，原始 EEG 继续保存；真实请求失败、失焦和采集故障仍会中止。

若页面还显示旧的“13.33–20.00 ms”范围，先完成或停止实验，再刷新页面核对前后端版本；后台仍旧时重新启动空闲服务。已打开页面不会自动加载新脚本。旧录制按原政策检查，不能通过刷新页面改变资格。

## “帧报告失败：请求失败 200”

HTTP 200 表示请求收到响应，不代表该批帧已接收。录制已结束或编号不匹配时，后端可返回 `ok=false, ignored=true`；旧页面会把它显示为“请求失败 200”。

当前页面会读取同一录制的实际结束原因并停止刺激。遇到此提示时，刷新页面并检查录制最终原因；不要仅按 HTTP 状态码判断网络故障。

## 无法合并录制或训练

同一受试者各轮使用相同 `subject`，使用不同 `recording_name` 区分轮次。身份、模拟/实机来源、目标数及编码契约需一致，每目标至少 6 个有效完整试次。相似名称不会自动被合并为同一身份。

若数据保存完整但有效试次为零，查看时序、信号质量和结束时钟复核的排除原因。补录时保留相同协议，修正具体问题后重新检查。
