# 协议实现与实机验收边界

源文档：父目录《万帆科技8通道EEG下位机通信协议.pdf》v1.0。

| 项目 | 实现 |
| --- | --- |
| 设备发现 | UDP 广播 `WHO_IS_EEG?` 到 3333，等待 `I_AM_EEG_DEVICE`，多次探测 |
| 控制 | TCP 3333，单客户端，每条命令单独 sendall，启用 TCP_NODELAY |
| 配置 | `5A 01 CONFIG1 CH_MASK`，等待 200 ms 后单独 START |
| 采样率 | 250:96，500:95，1000:94，2000:93，4000:92，8000:91 |
| 普通/阻抗/停止 | `5A02` / `5A05` / `5A03` |
| 清 Wi-Fi | 不提供 `5A04` 按钮或自动恢复操作 |
| 接收 | 本机 UDP3333，设备 IP 必须匹配当前 TCP 对端 |
| 格式 | AABBCCDD + u32 大端序号 + 50 × (3 状态字节 + 3N 通道字节) + CRC16 大端 |
| 电压 | 有符号24位大端值 × 4.5 / 24 / 8388607 × 1e6 μV |
| CRC | 序号+Payload，init FFFF、poly1021；当前按 CCITT-FALSE，标准向量123456789→29B1 |
| 丢包 | uint32 模差判断，重复/回退丢弃，正向丢包计数与清窗；坏CRC不推进序号 |
| 恢复 | 约1.2s无有效UDP先STOP/START，再有界重连，退避可取消；总重连预算5次 |
| 模式切换 | STOP、等待、排空UDP、START；请求与采集线程已应用模式不符时丢弃过渡包 |

单帧的三个 Status 字节被保留解析，但文档没有给出逐位解释，因此本应用不将这些位解释为接触、触发或模式标志。

CRC 文档未明确 refin/refout/xorout。当前实现经过独立向量、模拟硬件测试，并在 2026-09-19 的真实设备（250 Hz、8 通道普通 EEG）连续 868 包中通过校验，CRC 错误为 0。这确认了当前板卡在该配置下与 CCITT-FALSE 实现兼容；其它固件版本仍需核对。不要改为忽略 CRC。

设备没有命令 ACK、独立模式上报、设备采样时间戳或硬件触发字段。UI 的“已发送”和本地模式状态不等价于设备显式确认。停止和排空能降低跨模式旧包的风险，但协议本身不能严格识别极端延迟到达的旧模式 UDP 包。

修改采样率/通道必须停止旧会话，等待线程退出并关闭套接字，再建立新会话。网络恢复不会沿用旧分析窗口、旧预测或进行中的校准。

首次实机验收应确认：设备固件对应本协议、正确包长与电压极性、CRC正确、序号连续性、停止/重启行为、阻抗/EEG模式切换、电极位置映射、真实信号质量与提示时序。目前已验证定向发现、250 Hz/8 通道普通 EEG 的包长/CRC/连续序号与开始停止；电压极性标定、阻抗切换、其它配置和真实任务识别尚未验收。
